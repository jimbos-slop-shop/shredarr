Plex deletes

Plex can't send deletes to other apps, so Shredarr watches your library folders instead: when a movie or episode file Sonarr/Radarr know about disappears and stays gone for a couple of minutes, it's handled like a delete. Renames, upgrades and a disk going offline are recognized and ignored. To delete from Plex, turn on Allow media deletion in Plex → Settings → Library.

Jellyfin webhook

Jellyfin tells Shredarr about deletes through its Webhook plugin. Install it from Jellyfin → Dashboard → Plugins → Catalog, then let Shredarr set it up.

How Jellyfin reaches Shredarr. Use the server's IP if Jellyfin isn't on the same Docker network.
Path mappings

Only needed if your torrent client or Sonarr/Radarr see your files at a different path than Shredarr does. Example: the torrent client says /downloads/, Shredarr has the same folder at /data/downloads/.

Seeding rules

Give some torrents a different rule than the default. The first rule that matches wins, in this order: a torrent's own rule, then show or movie, then tracker, then category, then the default rule on the dashboard. "Never delete" protects matching torrents.

A tracker rule matches the tracker's name (for example TorrentDay, as Sonarr/Radarr and Prowlarr call it), which covers all of its announce addresses, or one announce host.

Cleanup behavior

What Shredarr does in Sonarr, Radarr and Seerr when you delete something in your media server.

Add an import exclusionWhen a movie or show is removed, stop import lists from adding it back.
Remove it from SeerrSo it can be requested again later.
Unmonitor deleted episodes and seasonsOtherwise Sonarr may download them again.
Remove deleted episodes' file recordsKeeps Sonarr's view of your library accurate straight away.
Delete cross-seeds together with the originalCross-seeds (the same release seeding from other trackers) are always cleaned up with the original. When this is off, each one first waits for its own tracker's seeding rule.

Deletion delay

After you delete something in your media server, Shredarr can hold on to its torrent for a while before removing it, even once the seeding rule is met. That gives you time to Undo a delete you didn't mean.

0 means no delay: the torrent is removed as soon as its seeding rule is met.

Low disk space

When the downloads disk runs low, delete waiting torrents early (oldest first) even if their seeding rule isn't met yet. Torrents still in your library, protected, or in their deletion delay are never touched.

RAR restore

Some releases come as RAR archives. If you delete one and then press Undo, Shredarr unpacks the archive again and hands the video back to Sonarr/Radarr.

Restore RAR releases with UndoShredarr unpacks the archive with its built-in unpacker. The torrent's files are only read, never changed.

    Saved .torrent files

    When Shredarr deletes a torrent for good, it keeps a copy of its .torrent file, so History → Redownload can add the same release back. Once that copy is removed, the same release can't be brought back through Shredarr: Redownload can only have Sonarr/Radarr search for a new one.
